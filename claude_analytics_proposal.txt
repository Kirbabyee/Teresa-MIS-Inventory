#### Claude's Proposed PostgreSQL / Supabase RPC Queries:

```sql
-- ═══════════════════════════════════════════════════════════════════════════
-- QUERY 1: Defect Rate by Section (uses existing inventory_items + joins)
-- ═══════════════════════════════════════════════════════════════════════════
SELECT
  s.id AS section_id,
  s.name AS section_name,
  t.name AS tab_name,
  COUNT(*) AS total_items,
  COUNT(*) FILTER (
    WHERE i.status ILIKE '%defect%'
    OR i.data::text ILIKE '%defect%'
  ) AS defective_items,
  ROUND(
    COUNT(*) FILTER (
      WHERE i.status ILIKE '%defect%'
      OR i.data::text ILIKE '%defect%'
    )::numeric / NULLIF(COUNT(*), 0) * 100, 2
  ) AS defect_rate
FROM inventory_items i
JOIN inventory_sections s ON i.section_id = s.id
JOIN inventory_tabs t ON s.tab_id = t.id
GROUP BY s.id, s.name, t.name
ORDER BY defect_rate DESC;


-- ═══════════════════════════════════════════════════════════════════════════
-- QUERY 2: Borrowing Compliance & Average Duration (borrowing_records)
-- ═══════════════════════════════════════════════════════════════════════════
SELECT
  COUNT(*) AS total_transactions,
  AVG(
    EXTRACT(EPOCH FROM (returned_at - borrowed_at)) / 86400
  ) FILTER (WHERE returned_at IS NOT NULL) AS avg_borrow_days,
  COUNT(*) FILTER (WHERE status = 'returned') AS on_time_returns,
  COUNT(*) FILTER (WHERE status = 'returned_late') AS late_returns,
  COUNT(*) FILTER (WHERE status IN ('borrowed', 'not_returned')) AS outstanding,
  ROUND(
    COUNT(*) FILTER (WHERE status = 'returned')::numeric /
    NULLIF(COUNT(*) FILTER (WHERE status IN ('returned', 'returned_late')), 0) * 100, 2
  ) AS compliance_rate
FROM borrowing_records
WHERE borrowed_at >= NOW() - INTERVAL '30 days';


-- ═══════════════════════════════════════════════════════════════════════════
-- QUERY 3: Security Threat Assessment (login_attempts_tracker)
-- ⚠ NOTE: This table has RLS enabled (service_role policy only).
-- ⚠ The anon key WILL FAIL here — must use service_role key or RPC.
-- ═══════════════════════════════════════════════════════════════════════════
SELECT
  COUNT(*) FILTER (WHERE suspended_until > NOW()) AS active_lockouts,
  COUNT(*) FILTER (WHERE lockout_tier >= 3 AND suspended_until > NOW()) AS high_severity,
  COUNT(*) FILTER (WHERE lockout_tier >= 5) AS permanent_bans,
  COUNT(DISTINCT email) FILTER (WHERE suspended_until > NOW()) AS unique_targets,
  COUNT(DISTINCT last_ip) FILTER (WHERE suspended_until > NOW()) AS unique_ips
FROM login_attempts_tracker;


-- ═══════════════════════════════════════════════════════════════════════════
-- QUERY 4: Suspicious IP Detection (brute-force pattern)
-- ⚠ Same RLS concern as Query 3.
-- ═══════════════════════════════════════════════════════════════════════════
SELECT
  last_ip,
  COUNT(DISTINCT email) AS targeted_accounts,
  COUNT(*) AS total_attempts,
  MAX(consecutive_failures) AS max_failures
FROM login_attempts_tracker
WHERE updated_at >= NOW() - INTERVAL '24 hours'
  AND last_ip IS NOT NULL
GROUP BY last_ip
HAVING COUNT(DISTINCT email) > 1
ORDER BY targeted_accounts DESC;


-- ═══════════════════════════════════════════════════════════════════════════
-- QUERY 5: Top Borrowers with Compliance Scores
-- ═══════════════════════════════════════════════════════════════════════════
SELECT
  br.borrower_name,
  br.borrower_id_number,
  br.borrower_role,
  COUNT(DISTINCT br.id) AS total_borrows,
  COUNT(*) FILTER (WHERE br.status = 'returned') AS on_time,
  COUNT(*) FILTER (WHERE br.status = 'returned_late') AS late,
  COUNT(*) FILTER (WHERE br.status IN ('borrowed', 'not_returned')) AS outstanding,
  ROUND(
    COUNT(*) FILTER (WHERE br.status = 'returned')::numeric /
    NULLIF(COUNT(*) FILTER (WHERE br.status IN ('returned', 'returned_late')), 0) * 100, 2
  ) AS compliance_rate
FROM borrowing_records br
WHERE br.borrowed_at >= NOW() - INTERVAL '90 days'
GROUP BY br.borrower_name, br.borrower_id_number, br.borrower_role
ORDER BY total_borrows DESC
LIMIT 20;


-- ═══════════════════════════════════════════════════════════════════════════
-- QUERY 6: Off-Hours Audit Anomaly Detection
-- ⚠ Uses UTC hours — if school is UTC+8, 8am local = 0am UTC
-- ═══════════════════════════════════════════════════════════════════════════
SELECT
  change_ts,
  table_name,
  action,
  changed_by,
  EXTRACT(HOUR FROM change_ts) AS change_hour,
  EXTRACT(DOW FROM change_ts) AS day_of_week
FROM inventory_change_logs
WHERE change_ts >= NOW() - INTERVAL '7 days'
  AND (
    EXTRACT(HOUR FROM change_ts) < 8
    OR EXTRACT(HOUR FROM change_ts) > 18
    OR EXTRACT(DOW FROM change_ts) IN (0, 6)
  )
ORDER BY change_ts DESC
LIMIT 50;


-- ═══════════════════════════════════════════════════════════════════════════
-- QUERY 7: Defect Rate Trend (time-series for charting)
-- ═══════════════════════════════════════════════════════════════════════════
SELECT
  DATE(change_ts) AS change_date,
  COUNT(*) AS total_changes,
  COUNT(*) FILTER (
    WHERE new_data::text ILIKE '%defect%'
  ) AS defect_changes,
  ROUND(
    COUNT(*) FILTER (WHERE new_data::text ILIKE '%defect%')::numeric /
    NULLIF(COUNT(*), 0) * 100, 2
  ) AS defect_rate
FROM inventory_change_logs
WHERE change_ts >= NOW() - INTERVAL '30 days'
GROUP BY DATE(change_ts)
ORDER BY change_date ASC;


-- ═══════════════════════════════════════════════════════════════════════════
-- QUERY 8: Inventory Utilization (borrowed vs available per section)
-- ⚠ Only covers legacy inventory_items — dynamic tables not included
-- ═══════════════════════════════════════════════════════════════════════════
WITH section_items AS (
  SELECT
    i.section_id,
    COUNT(*) AS total,
    COUNT(*) FILTER (
      WHERE i.status ILIKE '%defect%'
      OR i.data::text ILIKE '%defect%'
    ) AS defective
  FROM inventory_items i
  GROUP BY i.section_id
),
active_borrows AS (
  SELECT
    bi.inventory_section_id,
    COUNT(*) AS borrowed_count
  FROM borrowing_records br
  JOIN borrowing_items bi ON br.id = bi.borrowing_record_id
  WHERE br.status IN ('borrowed', 'not_returned')
  GROUP BY bi.inventory_section_id
)
SELECT
  s.name AS section_name,
  t.name AS tab_name,
  si.total,
  si.defective,
  si.total - si.defective AS available,
  COALESCE(ab.borrowed_count, 0) AS borrowed,
  ROUND(
    COALESCE(ab.borrowed_count, 0)::numeric /
    NULLIF(si.total - si.defective, 0) * 100, 2
  ) AS utilization_rate
FROM section_items si
JOIN inventory_sections s ON si.section_id = s.id
JOIN inventory_tabs t ON s.tab_id = t.id
LEFT JOIN active_borrows ab ON si.section_id = ab.inventory_section_id
ORDER BY utilization_rate DESC;
```

#### Claude's Key Design Decisions:

1. **All data from existing tables** — No schema changes, no new columns, no migrations needed
2. **Client-side aggregation** — Supabase returns raw rows via anon key; JavaScript computes metrics. Avoids need for SQL functions and works with RLS-disabled tables.
3. **Promise.allSettled** — Partial data renders even if one query fails (graceful degradation)
4. **Pure-function prescriptive engine** — `generateInsights(data)` is deterministic, testable, no side effects
5. **Brand-matched UI** — `#411111` primary, `rounded-xl bg-white shadow-sm border-slate-200/80` cards matching existing Dashboard
6. **Admin-only route guard** — `SecurityRoute requiredRole="admin"` matches existing Security/SystemSettings pattern
7. **Time range selector** — 7D/30D/90D/All, defaults to 30D, refetches on change via hook dependency

#### Claude's Self-Audit — Known Risk Areas (CRITICAL for Gemini to verify):

**RISK 1 — RLS BLOCKS login_attempts_tracker ACCESS (CRITICAL)**
The `login_attempts_tracker` table is the ONLY table in the schema with RLS **enabled** and a `service_role_all` policy. The implemented `fetchSecurityThreatAssessment()` calls `supabase.from("login_attempts_tracker").select("*")` using the anon key from `supabaseClient.js`. This **will fail silently or throw an RLS error** in production. The fix requires either: (a) using the service role key, (b) creating a Supabase RPC function that runs with `SECURITY DEFINER`, or (c) adding an anon-select policy if the data is non-sensitive.

**RISK 2 — Dynamic Inventory Tables Not Scanned (HIGH)**
The `analyticsApi.js` `fetchDefectRateBySection()` and `fetchInventoryUtilization()` only query the legacy `inventory_items` table. Dynamic tables created via Edge Functions (e.g., `inventory_computing_devices`, custom section tables) are completely excluded. Newer inventory sections will show 0% defect rate and 0% utilization even if they have data. The fix requires discovering dynamic table names via `inventory_settings` (key pattern: `inventory_tab_table.{tabId}`) and querying each one.

**RISK 3 — UTC vs Local Timezone for Off-Hours Detection (MEDIUM)**
The audit anomaly detection uses `getUTCHours()` for off-hours detection, but the school is in the Philippines (UTC+8). Stored timestamps in Supabase are UTC. The logic `hour < 8 || hour > 18` in UTC translates to 4pm–2am local time, NOT 8am–6pm local. The off-hours window is shifted by 8 hours. Should use `EXTRACT(HOUR FROM change_ts AT TIME ZONE 'UTC' AT TIME ZONE 'Asia/Manila')` in SQL or adjust client-side logic.

**RISK 4 — Compliance Rate Misleading When No Returns (MEDIUM)**
When all items are outstanding (0 returned), `complianceRate` defaults to `100%`. This could mislead admins into thinking compliance is perfect when there's simply no data. Should display "N/A" or "—" when `onTime + late === 0`.

**RISK 5 — Client-Side Aggregation Performance (LOW)**
`fetchInventoryUtilization()` fetches ALL `inventory_items` rows in a single query, then filters client-side. For small datasets (<1,000 items) this is fine. At 10,000+ items this could cause noticeable rendering delay. Consider a materialized view or PostgreSQL aggregation function for the utilization rate.

**RISK 6 — `actionTarget` Uses Hardcoded Paths (LOW)**
Insight action paths like `/inventory/${section.sectionId}` don't match the actual route patterns in `App.jsx` (which uses `/inventory/:sectionSlug`, not UUID). Slug-based navigation should be used instead. Also missing a route for the Analytics page itself (it routes to `/analytics` but insights link to it without a path).

**RISK 7 — Missing Import: `Search` (LOW)**
`AnalyticsDashboard.jsx` imports `Search` from lucide-react but never uses it. Should be removed to avoid lint warnings.
